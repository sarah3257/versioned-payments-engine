# גרסאות, תוקף ושחזור

## מדיניות ממומשת

- גרסאות רכיב מתווספות בלבד, עם מספר עולה. מותרות חפיפות כדי לאפשר תיקונים רטרואקטיביים.
- בתאריך האירוע בוחרים את הגרסה בעלת המספר הגבוה ביותר מתוך הגרסאות שבתוקף.
- לאחר בחירת הגרסה בודקים את תנאי השיוך שלה. לא בוחרים גרסה ישנה רק כי תנאי השיוך שלה מתאימים.
- מודל מפנה למזהי רכיבים בלבד. פרסום מודל בודק שיש כיסוי גרסאות לכל תקופת המודל.
- הסכמה נבחרת לפי EffectiveFrom האחרון שחל עד האירוע. לפני הסכמה ראשונה משתמשים בגרסת המודל המוקדמת ביותר: זו החלטת POC מפורשת שדורשת אישור עסקי.
- מחירונים, מס והסכמים נבחרים לפי תאריך, ובחפיפה לפי מספר גרסה גבוה. מדיניות החפיפות בנתוני ייחוס היא החלטת המימוש, מעבר לדרישה המפורשת לרכיבים, ודורשת אישור.

## RequestKey — מניעת כפילות

הלקוח מייצר מזהה לפעולה ושומר אותו גם לניסיון חוזר. מזהה ההשמה לבדו אינו מספיק: אותה השמה יכולה להופיע בחודש אחר או בחישוב חדש במכוון.

אותו RequestKey ואותו תוכן: מחזירים את התוצאה המקורית. אותו RequestKey ותוכן אחר: HTTP 409. כשל לפני COMMIT לא שומר תוצאה, וניסיון חוזר יכול לחשב שוב. אין שמירת ביניים עסקית.

## שחזור אינו חישוב מחדש

`POST /api/runs/{id}/replay` משתמש ב־PlanJson: הקלט, המחירים, הרכיבים, ההסכמים ושיעורי המס שנבחרו בריצה המקורית. הוא מריץ אותם שוב ומחזיר matchesOriginal. אין כתיבת תשלום נוסף.

חישוב חדש עם RequestKey חדש בוחר לפי המדיניות הנוכחית; לכן תיקון רטרואקטיבי עשוי לשנות את התוצאה החדשה. אין כאן חישוב הפרשים/זיכויים אוטומטי של תשלומים קיימים.

המערכת תומכת רק בגרסת מימוש engine-v1/template-v1. כדי לשמור שחזור אחרי שינויים בקוד, חובה לשמר מימושים היסטוריים או runtime ארכיוני ולהוסיף בדיקות רגרסיה. שינוי קוד במקום בלי שינוי גרסה יפר את ההבטחה.
