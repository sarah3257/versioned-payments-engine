# תהליך ההדגמה: השמה, טרנזקציות ופרסום מודל

1. **השמה חדשה**: מסגרת, מודל, תחילה וסיום, רמת תמיכה וסוג מסגרת. ״צור השמה וחשב״ יוצר טרנזקציות חודשיות עד המוקדם מבין סוף ההתחייבות וסוף השנה העסקית. חודש חלקי מחושב לפי ימים קלנדריים. כל החודשים מחושבים לפני שמירה; ההשמה, הריצות והטרנזקציות נשמרים יחד באותה טרנזקציית DB. מזהה בקשה חוזר עם אותם פרטים אינו יוצר כפילויות; שינוי פרטים תחת אותו מזהה נדחה.
2. **השמות**: חיפוש לפי מזהה השמה, בקשת היצירה או בקשת חישוב חודשית. פתיחת השמה מציגה תוצאה תקפה בכל חודש, גרסת מודל, סכום וסטטוס תשלום. פתיחת פירוט מציגה רכיבים, גרסאות ונימוקים. ההיסטוריה כוללת מקור, החלפה וביטול במינוס, ומסמנת שינוי שמקורו בפרסום מודל. אין כפתורי סימולציית תחזית במסך זה.
3. **פרסום גרסת מודל**: סימון מסגרות מסכימות, סימולציית השפעה וביצוע. לאחר הביצוע חוזרים להשמות ומרעננים את התיק כדי לראות אילו חודשים השתנו. המקור נשמר בהיסטוריה.
4. **בדיקת חישוב חודשי**: כלי מתקדם להזנה ידנית של תאריך אירוע ומקדם; אינו מסך יצירת השמה. אינו חלק מהתהליך העסקי הראשי.

API חדשים: `POST /api/placements/create-and-calculate`, `GET /api/placements/search?q=...`, `GET /api/placements/{id}/transactions`.

מזהה ההשמה קבוע לאורך חייה; מזהה בקשה מזהה פעולה. לשם חישוב חודשי נוסף סיומת YYYYMM למזהה בקשת היצירה. התוצאה התקפה נקבעת לפי MonthlyRevisions, ולא לפי סכימת רשומות היסטוריות או מספר גרסה גבוה בלבד.

בדיקות אוטומטיות: כמה חודשים עם החלפת גרסה לפי הסכמה, תיחום סוף שנה, חודש חלקי 4–6 בנובמבר, ניסיון חוזר ללא כפילות, כשל בחודש מאוחר ללא שמירה חלקית, וחיפוש/היסטוריה בעקבות פרסום מודל.

זהו POC: הנתונים ב־Vercel זמניים לכל מופע; ההתחייבות יכולה להימשך מעבר לתקופת החישוב הראשונית. המשך לשנה עסקית נוספת אינו מבוצע אוטומטית במסך היצירה.
