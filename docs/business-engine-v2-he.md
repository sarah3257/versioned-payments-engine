# הרחבת מנוע התשלומים

## הפעלה ותפעול

- ״השמות ותחזית״: יצירת השמה עם מזהה מסגרת ותקופת זכאות וחישוב תחזית ללא שמירה או עם שמירה.
- ״פרסום גרסת מודל״: בחירת מסגרות, בחר הכל, סימולציה ואז ביצוע. רק המסגרות שנבחרו עוברות גרסה.
- ״תשלומים וסטטוס״: סימון Header כשולם או ממתין. מקור שהוחלף או בוטל אינו ניתן לעריכה. כל שינוי מתועד.
- ״נתוני ה־DB״: טבלאות אחזקה וכוח אדם נפרדות, מסגרות, הסכמות, כותרות, פירוט, ביקורת והיסטוריית החלפות.
- ״כיסוי האפיון״: נתוני המקור שחולצו מה־Word והפניות לא תואמות.

## כללי חשבונאות

Paid: שומרים את המקור, מוסיפים כותרת במינוס עם Details שליליים וקישור למקור, ומוסיפים חישוב חדש. Pending: המקור מסומן Superseded והחישוב החדש הוא היחיד התקף. אין מינוס לתוצאה שלא שולמה. תיקון חוזר מתבסס על התוצאה התקפה; אילוץ ייחודיות מונע ביטול כפול של אותו מקור.

העריכה היא לצורך סימולציית תשלום ב־POC. אין תשלום חלקי או בנקאי ואין טענה שהכסף הועבר בפועל. PaymentStatus הוא סטטוס התשלום; CalculationRun.Status הוא סטטוס ההרצה.

## נתונים נפרדים

TAB_PriceListMaintenanceItem: מחיר פריט, יחידת מידה, תוקף וגרסה.
TAB_PriceListHuman: מקצוע, MonthlyAmount ו־HourAmount, תוקף וגרסה.
APP_MaintenanceItemComponent: PaymentPercent וחבויות.
APP_HumanComponent: TotalCountPosition וחבויות.

המרת שני התחומים למבנה משותף נעשית רק בחוזה ההרצה בזיכרון ולתאימות חוזה API קודם. מקור הנתונים והכתיבה הם הטבלאות הנפרדות; אין כתיבה לטבלת מחירון או מפרט משותפת. שדרוג DB ישן מעתיק פעם אחת את הנתונים ושומר את טבלאות המקור כגיבוי שאינו בשימוש המנוע.

## API נוסף

POST /api/institutions — מסגרת וסוף שנה עסקית (BusinessYearEndMonth/Day).
POST /api/placements — השמה; שם ובעלות נלקחים מהמסגרת לפי ID.
POST /api/headers/{id}/payment-status — Status, ExpectedStatus, Reason.
GET /api/headers — כותרות ופירוט, כולל ביטולים והיסטוריה; עד 1000 כותרות.
POST /api/forecasts — RequestKey, PlacementId, From, Simulation, Offset, PageSize. מפתח קבוע מאפשר ניסיון חוזר והמשך ללא כפילות.
POST /api/publications — חבילה אטומית Model/Components/Prices; Version=0 מקצה מספר הבא.
POST /api/versions/state — השבתה או סגירת תוקף עם סיבה, ללא שינוי גרסה מקורית.
GET /api/components/{id}/where-used — שימושים במודלים ובהשמות.
GET /api/export — מטה־דאטה ויומן פרסום ב־JSON.

כללי סוף תקופה, סטטוס תשלום ומסגרות כלולים בהוכחת הסימולציה. שינוי רלוונטי אחרי הסימולציה מחייב חישוב מחדש. נעילת הכתיבה היא בתוך תהליך אחד; אינדקסים, טרנזקציות ובקרת מקביליות מגינים ב־DB, אך אין בכך הוכחת תפעול בין כמה מופעים בענן.
