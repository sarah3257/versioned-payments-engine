מהגדרה עסקית לתשלום מוסבר

מפרסמים רכיבים מתבניות, מרכיבים מודל בשכבות ומקבלים תוצאות עם מקור לכל ערך. פרסום אינו משנה תשלומים קיימים; תיקונם נעשה באירוע חדש.

מסלול הפרסום

  1. מכינים גרסת רכיב או מודל
  2. בודקים ומריצים סימולציה ללא תשלום
  3. בודקים תוצאות והפרשים
  4. מפרסמים גרסאות קפואות

מסלול התשלום

  1. מקבלים אירוע ונתונים מתוארכים
  2. מחלקים לחודשים ומקטעים
  3. בוחרים גרסאות ומריצים שכבות
  4. שומרים תשלום והסבר יחד

תבנית היא חישוב משותף. רכיב עסקי מחזיק פרמטרים ותוקף. המודל מפנה למזהי רכיבים; הגרסה שלהם נבחרת בהרצה.

בחרו שינוי לדוגמה או ערכו חבילת פרסום. השינוי ייבדק ויחושב ב־Sandbox לפני שניתן לפרסם אותו.

חבילת הגדרות ומקרי סימולציה

עורך טכני לבדיקת חוזה הפרסום. נתוני הרכיבים והמודלים מוצגים עסקית בקטלוג.

סקירת השפעה לפני פרסום

כאן יוצגו תוצאות הסימולציה והפרשים.

שינוי בחבילה או במצב התשלומים מחייב סימולציה חדשה. פרסום אינו מבצע רטרו.

אותו מסלול משמש לחישוב, סימולציה ורטרו. לאחר שינוי נתונים, שולחים אירוע חדש עם גרסת מקור גבוהה יותר ואותה זהות השמה.

היכן מתבצעת הלוגיקה?

תנאים, סינון, צבירה ונוסחאות רצים ב־ZEN. מתאם קיבוץ משותף ב־.NET מחלק רשומות לקבוצות; סכומי הקבוצות מחושבים ב־ZEN. רכיבים באותה שכבה רואים רק את השכבות הקודמות.

לכל צעד נשמרים הביטוי והתוצאה. הטבלה נשמרת עם ראיות לתנאים שהתאימו ולא התאימו. הצגת העבר קוראת את התוצאה השמורה ולא מריצה קוד חדש.

גבולות ה־POC

המערכת מקומית עם נתונים סינתטיים. תהליך סליקה אמיתי, זהויות ארגוניות, רטרו מערכתי ותשתית ייצור בנפחים גדולים אינם חלק מהדגמה זו. האחסון הוא snapshots אטומיים ושמורים; לפני ייצור נדרש אחסון מנורמל ומדידות עומס.
